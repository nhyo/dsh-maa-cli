# 故障排查与常见问题

[← 返回 README](../README.md)

遇到问题先让 DSH 运行一次体检（`maa_doctor`），它会检查 maa-cli、目录、连接配置和 ADB 端口等 9 项。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 「请手动启动mumu模拟器！」 | 启动模拟器（并开启 ADB）后重新点确认，计划不会失效 |
| adb 连不上 | `adb devices` 检查；MuMu 需在设置中开启 ADB，默认端口 `16384` |
| `os error 17`（无法将文件移到不同的磁盘驱动器） | 目录被 EFS 加密。用 `cipher /d` 解密，或用 `mklink /J` 指到未加密的盘 |
| 运行时下载慢或失败 | 设置 `DSH_MAA_CLI_ASSET_URL` 指向镜像或离线 zip |
| 刚确认后很久没反应 | 可能正在每日自动更新 MaaCore（约 1 分钟），面板会显示「正在更新」 |
| 面板一直显示「执行中」 | 正常情况下每 3 秒自动刷新；若长时间不变，点「刷新状态」，或重启 DSH Desktop 让插件新版本生效 |
| 「停止失败」 | 进程 30 秒内没退出（例如被安全软件拦截），直接重试 |
| 「MAA 任务正在执行中」 | 同一时间只能跑一个任务，先停止或等它结束 |
| 「属于另一个 DSH 会话」 | 回到发起任务的会话操作 |
| 确认码无效 | 确认码一次性、30 分钟过期，重新准备计划即可 |
| 改了插件但行为没变 | 重启 DSH Desktop |

## 常见问题

**需要先装 MAA 吗？会影响我原来的 MAA 吗？**
不需要，也不会影响。插件用独立目录和环境变量与系统 MAA 隔离。

**为什么不把 MAA 打包进插件？**
MaaCore 和资源有几百 MB，且 MAA 采用 AGPL-3.0。按需下载更轻，也更容易跟随上游更新。

**能暂停任务吗？**
不能，MaaCore 没有可靠的暂停。可以立即停止，或设置「本局结束 / 再打 N 局 / Boss 前」停止。

**日志在哪？**
`~/.dsh/maa-cli/runtime/state/debug/`，也可以让 DSH 用 `maa_query` 查询 `log_dir`。
