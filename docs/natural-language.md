# 自然语言与策略

[← 返回 README](../README.md)

## 基本流程

直接说需求，例如「先启动游戏，基建换班，再刷 20 次 1-7，最后领每日奖励」：

1. 模型调用一次 `maa_prepare_plan`，生成有序计划。
2. 输入框上方出现确认面板，可以调整参数、填写备注；多步计划的每一步都可以点开单独修改。
3. 点「确认并执行 MAA」后在本地执行，**不再调用模型**。

确认码只对当前会话有效、一次性、30 分钟过期；DSH 重启后仍可确认。

## 备注

确认面板的备注栏可以写额外要求（如「优先招募结城理，让他在前方堵门」）。离开备注栏时自动解析：

- 先用本地规则和策略记忆编译；
- 只有本地无法确定的部分才交给模型规范化（纠正错别字，把「抓/拿/捞/选」统一理解为招募），再由本地编译；
- 解析成功后才能确认，无法执行的部分会说明原因。

## 策略编译

肉鸽或战斗策略会被编译成 MAA **真正读取**的资源或作业文件，而不是只保存一段文字。

支持：

- 调整肉鸽干员的招募、技能、精二优先级；招募表里没有的干员会校验后补上
- 重设开局阵容条件
- 调整藏品购买顺序或禁买
- 修改已收录事件的优先选项
- 生成 Copilot 部署、技能、撤退等动作，支持坐标、方向、费用、延迟、击杀数条件
- 「堵门」「守蓝门」：不写关卡时对该主题全部关卡自动选点和朝向（按地图数据和干员地面/高台位置）
- 一句话里包含多个要求

安全与回退：

- 肉鸽策略通过 maa-cli 的 `--user-resource` 临时覆盖，执行前备份、结束后恢复，MAA 原始资源只读。
- 不存在的干员、藏品、事件、关卡不会被猜测，会列出原因。
- Copilot 是预编排动作，不是实时战术 AI；需要临场判断的要求会说明无法实现。

## 策略记忆

验证通过的策略会按最小单元保存到 `~/.dsh/maa-cli/strategy-memory.json`：

- 保存的是规范化后的 MAA 动作，不是原句，所以同义说法能命中同一条记忆。
- 每类最多 20 条；冲突的要求不执行也不保存；本次明确指令覆盖旧偏好。
- 复用前仍检查版本、主题、地图并重新预览；「堵门」不保存坐标，每次按当前地图重算。
- 模型可通过 `/maa strategies`、`/maa strategy-enable|disable|delete` 查看和管理。

## 自动肉鸽面板

计划含肉鸽步骤时，确认面板显示「自动肉鸽参数」：主题、模式、难度、刷取次数、分队、职业组、开局干员、助战。

- 选项从当前 MAA 资源读取，资源更新后面板每 15 秒自动刷新，不用重启 DSH。
- 难度默认「MAX」，确认时换算成当前主题的最高难度。刷取次数默认 9999。
- 每个主题分别记住上次确认的设置。
- 「高级设置」只显示当前主题和模式下 MAA 实际会用的开关：

| 开关 | 出现条件 |
| --- | --- |
| 使用非好友助战 | 使用助战 |
| 打到最终 Boss 停 | 非傀影主题 |
| 等级刷满停、投资源石锭 | 总是 |
| 投资次数、投资满停 | 投资源石锭 |
| 投资后购物 | 刷源石锭模式 |
| 凹精二直升、只凹精二直升 | 凹开局模式 |
| 月度小队 / 深入调查自动切换 | 对应模式 |
| 常乐节点 | 刷常乐节点模式 |
| 使用密文板、检测坍缩范式 | 萨米 |
| 骰子刷新商店 | 水月 |

手动确认也可以带参数，例如 `/maa confirm MAA-1A2B3C theme=Sarkaz mode=0 difficulty=4`。
